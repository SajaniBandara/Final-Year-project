1. Optimization (done and committed)
Profiling showed 66-73% of simulation CPU was one function (updateTxop), rebuilding a time value inside a per-neighbour loop on every packet event. After hoisting loop-invariants, caching neighbour lists, and bounding one RL loop to real node ids, identical runs are 4.0x (A1) to 4.8x (A5) faster. Detector windows, TCAM, trust and FlowMod outputs are byte-identical to the old binary; only wall-clock timing columns differ. A 300 s A1-A4 run drops from about 90 min to about 20 min (estimate; I measured 60-150 s runs with three jobs in parallel, not yet a full 300 s sweep).
During the audit I also found that the FlowMod endorsement list was never reset per cycle and did not reject a repeat endorser, so the f+1 quorum was cumulative. It is fixed. Results are unchanged, because every cycle's 64 endorsers exceed f+1 = 22.
