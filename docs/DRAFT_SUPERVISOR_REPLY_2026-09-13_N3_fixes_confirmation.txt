Fix 2 -- one clean No-ZeroTrust toggle that does not silence signing.
  New flag --no_zero_trust_arm, applied once in main() right after cmd.Parse().
  It does exactly three things and nothing else:
    - forces N_Controllers = 1;
    - skips the distributed key-generation ceremony (dkg_setup.h) -- keys are
      provisioned per node on demand instead, so this does NOT set
      g_disable_crypto;
    - clears enable_endorsement_requirement, so the single controller commits
      FlowMods unilaterally (blockchain write access) rather than needing f+1
      RSU endorsement.
  Your acceptance test was that signing, STARK proofs, batch verification and
  witness alert signing all stay active in this arm. They do -- confirmed from
  the run's own crypto outputs, not from the debug prints (those are compiled
  off):
    No-ZeroTrust crypto_timing_log: 420,385 rows, ops present = sign, verify,
      stark_hop, batch_verify, consensus.
    sig_valid_rate = 0.983, stark_timing_fail = 0, stark_hop_fail = 0 (proofs
      verifying), witness_nfa_count = 3 (witness path active).
  So the flag conflates nothing: DKG is gone, the four crypto mechanisms remain.

Fix 3 -- a counter that confirms a quarantine blocked something.
  Added a counting helper at the five enforcement guard sites, incremented only
  when quarantine_blocks() returns true and the guard actually aborts the action.
  It tracks distinct nodes denied an action (blocked_nodes) and raw guard-site
  aborts (block_events), printed at end of run alongside the quarantined-node
  count. The two hidden-forwarding guards are recorded beside the existing if
  without touching it, so the RNG draw order -- and the simulation -- is
  unchanged. Confirmed:
    Full NEXUS:    quarantined = 26, blocked_nodes = 24, block_events = 864
    No-ZeroTrust:  quarantined = 46, blocked_nodes = 42, block_events = 1728
  blocked_nodes is strictly lower than quarantined in both arms (24 < 26,
  42 < 46), not identical by construction: in each arm two quarantined nodes were
  never caught attempting an action after containment, so they count as
  quarantined but not blocked. That is exactly the "fired vs blocked" distinction
  N3 needs.
