1. FIXED — stale claimed-forward timestamps (b7c8af1)
-------------------------------------------------------

backing array is never cleared while packet_id restarts every cycle, so reads
collided across cycles. S2's hop_delay was measuring elapsed cycles, not an
actual hop. Now reads from the packet tag (previous_senderId/previous_timestamp,
already serialized at every tagging site).

the other 412 were fabricated readings on a node that happened to be malicious

2. FIXED — synthetic TCAM-generator samples raising real S1 accusations (20ede88)
-----------------------------------------------------------------------------
tcam_flow_generator.h called the real s1_detect_packet() with a hardcoded
1.5ms constant and a VEHICLE as sender_node_id, contradicting that function's
own contract (sender_node_id = the RSU that applied the delay). Every firing
from this path was false by construction, and it ran ungated in every attack
variant, polluting Attack 1's confusion matrix even during unrelated runs.

4. FIXED — S1 masking itself (033210a)

6. STRUCTURAL FINDINGS NEEDING A DECISION
-----------------------------------------------------------------------------
6.1 S1 cannot affect M1 at all. dw_mark_obu() (where S1 lives) marks OBU rows;
    M1 scores RSU rows only. Confirmed empirically — after fixing S1
    (item 4), it fired 2.7x more often and M1 was byte-identical. A1's M1 is
    carried entirely by S2. Decision needed: should M1 incorporate OBU rows,
    or should S1 be reported separately?

6.2 Per-node matrix is coverage-only and run-length-dependent. Same config
    scored 55.6% precision at 20s, 26.6% at 90s — state run length whenever
    per-node figures are quoted.

6.3 Recall ceiling is 26, not 32 — 32 RSUs marked malicious via controller
    compromise, only 26 ever apply a delay. Recall against the detectable set
    is 17/26 = 65%, not 53%.

6.4 Adding components makes results WORSE. Q5 macro 0.632 -> Q6 macro 0.590.
    A3 collapses to -0.007 (worse than random) once LSTM+witness+BTMM are
    added. Sharpest unexplained anomaly in the table.

6.5 Monotonicity is still ill-posed. Q3 is LSTM-only, Q4 witness-only, most
    variants have no value there (Q3 macro -0.020, Q4 exactly 0.000
    everywhere) — raised three times, still needs a scoring decision.
